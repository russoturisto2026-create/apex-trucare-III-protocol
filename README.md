# Протокол инсулиновой помпы TruCare III

Легитимное изучение **протокола самой помпы TruCare III** — команд, которые помпа принимает, и
ответов, которые она отдаёт по радиоканалу. Официальное приложение **Erwin Blueberry**
(v1.0 Build 489 Patch1) используется **только по прямому назначению** — как штатное средство
управления помпой; само приложение объектом изучения не является. Работа ведётся на **тестовом
стенде**: помпа к человеку не подключена. Механизмы обхода защиты не применяются — фиксируется
только то, что уже проходит по радиоканалу и видно на экране. Помпа и приложение — собственность
автора исследования.

## Что где лежит

| Файл | Назначение |
|---|---|
| `RESEARCH.md` | Протокол исследования — журнал по шагам, со ссылками на исходные материалы. |
| `PROTOCOL.md` | Техническое описание протокола — управляющие команды и объекты ответа, со ссылками на шаги. |
| `MATERIALS.md` | Реестр исходных материалов: № → тип → описание → шаг → архив. |
| `user_agreement.md` | Зафиксированная версия лицензионного соглашения приложения. |
| `.claude/skills/apex-device/` | Навык подключения к стенду и снятия материалов (HCI, скриншоты). |
| `archive/` | Все исходные материалы, только в архивах, **вне git** (см. `.gitignore`). |

Прослеживаемость: `PROTOCOL.md` → шаг в `RESEARCH.md` → № материала в `MATERIALS.md` →
архив `archive/<исследование>/NN-*.zip`.

## Правила проекта

1. **Один шаг — один коммит.** Шаг — осмысленная единица наблюдения. Сообщение коммита ссылается
   на шаг и на номера архивов.
2. **Материалы под номерами и SHA-256.** Каждый снятый материал получает сквозной номер и
   **SHA-256 исходного файла** — независимое доказательство целостности; всё регистрируется в
   `MATERIALS.md`. Хэш считается по самому файлу-артефакту (тому, что лежит внутри архива);
   проверка целостности — извлечь файл и сверить `sha256sum` с записью в реестре. Сами файлы —
   только в архивах вне git.
3. **Архивы шага, раздельно по типам.** Материалы шага пакуются в `archive/<исследование>/`:
   `NN-hci.zip` (только извлечённый `btsnoop_hci`), `NN-screens.zip`, `NN-photos.zip`. Полный
   bugreport не сохраняется.
4. **Двусторонняя привязка.** В `RESEARCH.md` — ссылки на материалы; в `PROTOCOL.md` — ссылки на
   шаги `RESEARCH.md`. Утверждение без ссылки на доказательство не заносится.
5. **Приватность.** Ни в одном текстовом документе не приводятся персональные данные, пароли,
   серийные номера, адреса устройства и идентификационные блоки — только плейсхолдеры
   (`<identity>`, `<serial>`, `<crc>` и т.п.). Скриншоты/фото с чувствительными данными
   кадрируются/замазываются.
6. **Самодостаточность.** Документы этого проекта опираются только на собственные материалы; в них
   нет ссылок на сторонние проекты, их файлы и пакеты.
7. **Статус меняется только по доказательству.** Рядом с выводом всегда ссылка на шаг и материал;
   при противоречии материалов — статус «требует перепроверки», а не «подтверждено».
8. **Достоверность: ≥2 измерения с различными характеристиками.** Утверждение (наличие поля, его
   кодирование, семантика команды/ответа) переводится в статус «подтверждено» только после
   воспроизведения минимум в двух измерениях, различающихся характеристиками — разное значение
   параметра, разное состояние устройства/сессии, разные условия связи, или сверка «радио ↔ экран».
   Хотя бы одно из подтверждений должно быть независимым по природе (не повтор того же действия).
   Одно измерение — «предположение», два и более согласованных — «подтверждено».
9. **Только наблюдение.** Фиксируем обмены, инициированные официальным приложением (ведётся
   вручную). Собственных кадров помпе не отправляем, защиту не обходим. Терапевтические команды
   выполняет приложение на стендовой помпе, не подключённой к человеку.

## Порядок исследовательского шага

1. Подключиться к стенду (навык `apex-device`).
2. Выполнить сценарий в приложении вручную.
3. Снять материалы: `bugreport` → извлечь `btsnoop_hci` (bugreport удалить); при необходимости —
   `screencap`; фото делает пользователь. Присвоить материалам номера.
4. Разобрать HCI, описать шаг в `RESEARCH.md`, занести материалы в `MATERIALS.md`.
5. Обновить `PROTOCOL.md` со ссылкой на шаг (со статусом «предположение»/«подтверждено»).
6. Упаковать материалы в `archive/<исследование>/NN-*.zip`.
7. Один коммит на шаг.
