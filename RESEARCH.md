# Протокол исследования

Хронологический журнал изучения **протокола помпы TruCare III** — команд, которые помпа принимает,
и ответов, которые она отдаёт. Приложение **Erwin Blueberry** используется только как штатное
средство управления помпой и само не изучается. Одна запись — один шаг (и один коммит). Каждый шаг
ссылается на исходные материалы по номерам из `MATERIALS.md`; выводы шага переносятся в
`PROTOCOL.md` со ссылкой на этот шаг.

Правила ведения — в `README.md`. Ключевое: вывод получает статус **«подтверждено»** только после
≥2 измерений с различными характеристиками (правило 8); до этого — **«предположение»**.

Легенда статусов: 🟡 предположение · 🟢 подтверждено · 🔴 требует перепроверки.

### Шаг 001 — Подключение помпы: топология GATT, MTU, включение уведомлений
- **Дата/время:** 2026-09-16, подключение ~16:22 (захват 16:21–16:25).
- **Исследование:** `etap-A-transport-gatt`.
- **Действие:** пользователь штатно подключил помпу через приложение (перезапуск приложения →
  подключение к помпе → экран «Устройства» со статусом помпы). Приложение велось вручную;
  собственные кадры помпе не отправлялись (только наблюдение).
- **Материалы:** №1 (HCI-захват; из идентификаторов наблюдался только адрес помпы),
  №2 (скриншот «Устройства», серийный номер замаскирован).
- **Разбор:** `tools/hci_topology.py` по материалу №1.
- **Наблюдения:**
  - GATT-сервер помпы: службы `0x1800`/`0x1801`/`0x180A` и вендорские `0xFFE0`, `0xFFE5`,
    `0xFF90`, `0xFFC0` (диапазоны handle — PROTOCOL.md §1.1).
  - MTU: запрос `517` → выдано `251`.
  - Канал ответов помпы: `0xFFE4` (`0x001C`, NOTIFY) — за сессию 40 уведомлений; включён
    записью `01 00` в CCCD `0x001D`.
  - Канал команд: `0xFFE9` (`0x0021`, WRITE/WRITE_NR).
  - Канал `0xFFC0`: `0xFFC1` (WRITE) + `0xFFC2` (NOTIFY, CCCD `0x0045` включён `01 00`,
    1 уведомление) — предположительно авторизация; детально в Этапе B.
  - Сверка радио↔экран: экран показал прошивку `1.1.1`, версию протокола `4.12`, батарею
    `1,36 В`/`46%`, статус «Разблокирована». Сопоставление этих значений с конкретными кадрами
    ответов — задача Этапа D.
- **Вывод:** топология транспортного уровня зафиксирована в PROTOCOL.md §1 со статусом
  🟡 предположение (одно измерение). Для 🟢 требуется повторный захват с иными характеристиками
  (переподключение / после перезагрузки телефона) — топология должна совпасть.
